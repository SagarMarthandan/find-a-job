# Changelog

## Unreleased

- Added a localhost-only FastAPI service with private session-token authentication, SQLite task state, uploads, harness claim/complete/fail routes, evidence validation, and review-only PDF output.
- Added the `find-a-job` CLI and a discoverable portable `SKILL.md` with YAML metadata, persistent service startup, and host-side claim-loop instructions.
- Added pinned Python packaging and setup/diagnostic documentation. Setup commands remain separate from paid service connectivity checks.
- Aligned headed Playwright screenshot names with the artifact registry (`browser.png`) and added dashboard task-detail stability, focus restoration, harness connection status, and blob URL cleanup.
- Added behavioral tests for wrong-owner completion, late completion after cancellation, source-evidence validation, and private URL refusal.
- Made the candidate-source intake the first workflow: one task preserves every resume, catalog, notes and selected GitHub source identity; extracts PDF, Markdown/TXT, DOCX tables, ODT, XLSX, PPTX, RTF, JSON/YAML, CSV/TSV, HTML/XML and configured source-code text; and retains unsupported/scanned inputs with errors. Limits: 25 sources, 10 MiB/file, 50 MiB/request, 100000 characters/document, 1 MB aggregate text and 40 MiB expanded Office ZIP.
- Rejected new generic `kind: "profile"` task creation in favor of `/api/intakes`; enforced source-specific evidence quotes, pending-source gating, explicit failed-source acknowledgment, correction-driven approval invalidation and the downstream resume gate. The dashboard supports editing an already approved intake and requires reapproval after changes.
- Added workspace-local extraction caching and approved-intake context retrieval through the authenticated API and offline CLI. Context revisions bind the approved profile to full source snapshots; stale resume consumers are rejected. Verified on 2026-10-21: `.venv/bin/python -m unittest discover -s tests` passed all 22 tests. A synthetic local HTTP/CLI smoke confirmed identical multipart upload miss/hit with fresh IDs and no approval reuse, source-quoted profile approval, authenticated context miss/hit and unauthenticated 401, correction/reapproval revision change, offline CLI hits after service shutdown, empty-extraction non-caching, and workspace isolation. The smoke used no browser tasks, external/provider calls, or real candidate data. The suite passed corrupt-cache rebuild and stale-resume checks.
- Added Stage 2 role discovery and job search. Approved profiles generate versioned, evidence-cited role suggestions with model-scoped caching; candidates save selected/custom roles and all search filters per intake. A browser worker visits the eight native source adapters, captures visible listing/detail pages and screenshots, and persists an immutable acquisition snapshot. Host assessments are validated against exact captured pages, duplicate URLs are merged, and the backend applies deterministic tri-state eligibility for experience, seniority, location, remote eligibility, radius, dates, employment, languages, excluded titles and seen/applied history. Ambiguous remote/worldwide and unsupported radius remain review states. Fixed role/config staleness, cancellation, all-source failure and per-country Indeed domains.
- Stage 2 verification on 2026-10-21 passed all 39 tests and a synthetic HTTP/CLI/harness smoke. Role cache miss/hit and model isolation, custom-role persistence, source host impostor rejection, multi-country Indeed URLs, evidence parsing, duplicate merge, stale revision/cancellation, partial and total source failure, history isolation and dashboard rendering were exercised. A live visible-browser Arbeitnow search discovered 69 links and captured two detail pages with screenshots; the dashboard showed a deterministic `review` decision. LinkedIn, Indeed, XING, Stepstone, Wellfound, EU Remote and ATS were capability/URL-checked only, not live-verified.
- Stage 2 correction verification on 2026-10-21 passed all 49 tests. Suggested-role title edits now save under the suggestion id and feed source queries through the edited title plus aliases; the dashboard saved `Platform Engineer` as revision 1 with `custom: false`, and generated Arbeitnow URLs contained `Platform+Engineer` and `python`. City filters now require the selected city, with Berlin/Paris, York/New York and Kiel/Kielce regressions; countries and cities are separate constraints and partial country/city evidence remains unknown. Core title/company/location values must occur in their own normalized quotes. Years ranges anchor to the minimum required bound and optional wording is rejected. Posting eligibility uses quote precision intervals, so same-day timestamp choices cannot change a 24-hour decision, date-only uncertainty can become review, and future dates exclude. Zero experience and non-finite numbers are covered. The correction smoke used a fresh synthetic workspace and did not browse a live job source. Limits: radius remains unknown because adapters expose no distance evidence; adapters do not paginate listings beyond the configured detail cap; live coverage remains Arbeitnow only from the earlier run.
- Stage 2 final smoke on 2026-10-21 passed all 49 tests (8.252 s) and exercised the actual dashboard plus CLI against a synthetic approved intake: role suggestions completed, the suggested role title was edited, filters were saved, and no browser navigation occurred until Start. The subsequent live headed Arbeitnow run discovered 70 listing links, captured 10 detail pages and 24 artifacts, and produced 3 assessed jobs (0 match, 2 review, 1 excluded); all 12 screenshots loaded in the dashboard. Other seven adapters remain live-unverified, configured radius remains unknown, and listing adapters do not paginate beyond the detail cap.
- Known unresolved Stage 2 parser false negatives from that live smoke: an explicit `5+ years` requirement under a multiline `Requirements` heading was not recognized, and compact posting-age labels (`1w`, `3w`, `1mo`) were treated as unknown. Those cases therefore stayed in `review`/unknown rather than being evaluated. Code and tests were not changed for these findings.
- Repository development policy now permits only `opencode-go/deepseek-v4.1-flash` as the execution worker; GPT-Luna-6 is not an execution worker or fallback.
- Complexity: touched Stage 2 functions were measured with a manual AST decision-point counter because `radon` was unavailable; every touched function measured at CC <= 10, including `_years_supported` (10), `_job_posted_interval` (10), `_posting_state` (7), `_geography_state` (5), `_require_evidence` (8) and `_selected_role` (9).
- Intake smoke on 2026-10-20 used 19 synthetic sources and a real visible-browser capture of `https://github.com/octocat/Hello-World`; 17 sources extracted and scanned PDF/DOC failures remained visible. Selected-model consolidation, wrong-source/invented-claim rejection, UI correction/approval/exclusions, approval invalidation, resume gate, and persistence after restart were exercised. All nine unittest cases passed.
